# Flow: Waitlist / Pre-Launch

Read this after intent is identified as waitlist / pre-launch. It overrides and extends `interview/INTERVIEW.md`'s generic questions — ask these on top, not instead.

## Ask these, on top of the generic 5

1. **When are you launching?**
   Specific date → countdown urgency is honest, use it. "Soon" → don't fake a date; use vaguer urgency framed as early access instead.
2. **What's the hook — why should someone care before it exists?**
   The problem being solved must be strong enough to sell the vision alone. There's no product demo to fall back on.
3. **Any early access perks?**
   Discount, first access, founding-member status, input on features. This is what makes signing up for nothing worth it.

## Section Template

1. Hero: problem statement + vision + email capture CTA
2. Brief explanation: what it will be, who it's for — 2-3 sentences max
3. Early access benefits: what signers get that later signups won't
4. Optional: founder story or mission statement — why this is being built
5. Email capture CTA, repeated at the bottom

## Copy Direction

- This is the SHORTEST page type — under 100 words of copy is the target.
- Sell the problem and the vision, NOT features that don't exist yet.
- One CTA only: email capture. No name field — just email (Miller's Law: fewer fields, fewer decisions).
- Countdown timer only if a real launch date exists — a fake one violates Honest Scarcity (PRINCIPLES.md 3.10).
- "Join 1,247 others on the waitlist" — real number, updates over time. Never round up, never invent it.

## Edge Cases

- Pre-launch with a working prototype → include a demo video or screenshots; the page can run longer.
- B2B waitlist → add a company name field, maybe role — helps qualify leads without adding real friction.
- Multiple products → one waitlist page per product. Never combine — it splits the vision two ways.
